# Cotsel weekly blocker register

## Register control

| Field            | Value                                                                                                       |
| ---------------- | ----------------------------------------------------------------------------------------------------------- |
| Control          | REPORT-01, defined in `docs/readiness/cotsel-governance-register-v1.md` §5                                  |
| Governing issue  | [#637](https://github.com/Agroasys/Cotsel/issues/637) — `wp0-governance`                                    |
| Owner            | Programme Lead @Astton                                                                                      |
| Cadence          | Weekly, and whenever a P0 readiness item changes materially                                                 |
| Canonical status | [Project 9 — Cotsel Production Readiness and Controlled Pilot](https://github.com/orgs/Agroasys/projects/9) |
| Edition rule     | Append a new dated edition. Do not rewrite an earlier snapshot; correct it in the next edition.             |

An item is a current blocker when Project 9 classifies it as P0 and its status is `Blocked`, `Decision Required`,
or `Evidence Review`. An unstarted Backlog item is not reported as a current blocker merely because it is not yet
accepted. This definition keeps the register useful for decisions without disguising the complete Project plan as
an active-blocker list.

Each edition is reconciled by running:

```bash
GH_TOKEN="$(gh auth token)" pnpm run readiness:cotsel:audit-live
```

The audit validates the source contract, rendered issue bodies, and Project 9 field values. The register then
records the matching live P0 blocker set, its owners, and the next decision. A green audit is evidence of
metadata consistency; it is not acceptance of any item below.
