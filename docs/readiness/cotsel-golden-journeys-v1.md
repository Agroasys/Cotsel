## Authority boundaries

Every journey below inherits these boundaries from SOW rows AUTH-01 through AUTH-09. A journey assertion that
contradicts this table is a defect in the journey, not in the boundary.

| Domain                                  | Authoritative system                                                                    | Explicitly not authoritative                                   |
| --------------------------------------- | --------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| End-user identity and roles             | Agroasys identity and backend                                                           | Cotsel session cache, frontend profile, unverified token claim |
| Participant balances and wallet history | Agroasys participant ledger                                                             | Cotsel dashboard projections                                   |
| Order payment intent and reservation    | Agroasys backend                                                                        | Browser acknowledgement, optimistic frontend retry             |
| Escrow execution and fee accrual        | `AgroasysEscrow` on Base, via emitted events                                            | Gateway acceptance, submitted transaction, indexer status      |
| Operator approval and signing           | Gateway audit **plus** decoded signer response reconciled to chain result               | Unverified managed-signer response                             |
| Chain event truth                       | Canonical Base chain                                                                    | Indexer checkpoint state taken alone                           |
| Treasury entitlement and close          | Finalized canonical contract events plus fresh reconciliation evidence                  | Unfinalized event, failed handoff row                          |
| Fiat and off-ramp completion            | Regulated provider or bank                                                              | Cotsel `CREATED`, `FAILED` or unverified callback state        |
| User-visible settlement status          | Agroasys backend, after confirmed Cotsel evidence, chain state and reconciliation agree | Cotsel or dashboard status shown ahead of reconciliation       |

## Common rules

- Every run binds to one release manifest identifying application digests, migration identity, chain ID,
  contract address, ABI hash, provider mode and redacted configuration digest. A material change to any of
  these invalidates the run.
- A mock proves local logic only. It never substitutes for chain, provider, network, persistence or
  cross-repository evidence.
- A retry uses the documented idempotency key. A timeout never becomes success without authoritative evidence.
- Every journey carries one privacy-safe correlation identifier across browser, backend, gateway, signer,
  chain and reconciliation records.
- No secret material, raw signer payload, unredacted authorization or participant personal data enters an
  issue, log or evidence index.
- Rejection must be safe and observable, and must leave no ambiguous financial or chain state.
- A journey is specified here and **accepted** only in the candidate-specific gate review named in its row.

## Manual decision checkpoints

These decisions are made by named authorities under WP-0 governance (#637). A journey records the decision; it
never invents one.

| Checkpoint                               | Authorized decision                                                                  | Accountable owner                                            | Authoritative record and safe failure                                                               |
| ---------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| Settlement or reconciliation discrepancy | Freeze, retry, correct or escalate after the technical owner identifies the mismatch | Finance authority, on Cotsel and Agroasys technical evidence | Reconciliation report, chain evidence, decision log entry. Missing evidence keeps finality pending. |
| Treasury handoff release                 | Two-party maker-checker approval before external handoff or close                    | Treasury authority                                           | Maker and checker identities, provider receipt, close record. One-person approval fails closed.     |
| Emergency pause or freeze                | Any authorized operator may pause. Unpause requires quorum and incident approval.    | Incident Commander                                           | Contract pause events, incident record, quorum approval. Unilateral unpause is rejected.            |
| Residual security risk acceptance        | Accept a bounded exception with scope, compensating control and expiry               | Security authority                                           | Signed risk record per GOV-05. An unbounded or expired exception blocks the gate.                   |
| Provider or off-ramp exception           | Accept or reject a provider state conflict                                           | Finance and Compliance authorities                           | Provider receipt, decision log, reconciliation effect. Unverified callbacks cannot close a handoff. |
